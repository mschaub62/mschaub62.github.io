The artifact

The algorithms and data structure artifact is my OpenGL 3D scene project from CS-330, built in C++ and OpenGL. The program renders a 3D scene using shapes, textures, lighting, camera controls, and projection settings. Behind the visuals it uses arrays, structured logic, object rendering, and OpenGL resource management.

Why it's included

I selected this artifact because it shows more than a picture on screen. It shows how code organizes textures, manages objects, and controls how a scene is displayed. That makes it a strong algorithms-and-data-structures example: the program stores texture information in a fixed array, uses logic to control rendering behavior, and requires careful handling of resources.

What changed in the enhancement

Corrected the projection logic. In the original, the function that reports whether orthographic projection is active always returned false instead of the real state. I corrected it to return the stored projection value, so the rest of the renderer makes decisions on accurate information.

BEFORE · always false
bool ViewManager::IsOrthographic...() const
{
    // ignores the real state
    return false;
}
AFTER · returns real state
bool ViewManager::IsOrthographic...() const
{
    return bOrthographicProjection;
}

Fixed the texture cleanup. The original cleanup routine called glGenTextures, which creates textures instead of releasing them. I changed it to glDeleteTextures, reset the texture IDs, cleared the texture tags, and reset the loaded-texture count, so GPU resources are actually freed.

BEFORE · leaks resources
for (int i = 0; i < m_loadedTextures; i++)
{
    glGenTextures(1, &m_textureIDs[i].ID);
}
// nothing is released; count never reset
AFTER · releases & resets
for (int i = 0; i < m_loadedTextures; i++)
{
    glDeleteTextures(1, &m_textureIDs[i].ID);
    m_textureIDs[i].ID = 0;
    m_textureIDs[i].tag = "";
}
m_loadedTextures = 0;

Added boundary checking. Because the program uses a fixed texture array, I added a check that prevents loading more textures than the array can safely hold, and I improved error handling for unsupported image formats so image memory is released before the function exits. These changes made the program safer and more reliable.

Reflection

This process taught me that a program can work visually and still have problems in the code behind it. When I first created the project, my goal was simply to get the scene to render. Reviewing it now let me look at the project the way a developer reviews legacy code, checking logic, managing resources correctly, validating boundaries, and writing code another developer could follow.

The biggest challenge was improving the artifact without breaking the existing 3D scene. OpenGL projects have many connected parts, shaders, meshes, textures, lighting, and camera controls, so I made targeted corrections rather than restructuring the whole renderer. Moving repeated rendering logic into reusable helper methods is a sensible next step, but these changes were a solid step forward and made the artifact stronger across algorithms, software design, and defensive programming.
